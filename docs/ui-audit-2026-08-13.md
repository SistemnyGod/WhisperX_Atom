# WhisperX Atom Desktop UI audit — 2026-08-13

## Scope

This audit covers the WinUI 3 Desktop shell and the first-run recording flow. AudioGraph, Recorder Host/Service, IPC, spool, delivery, backend and processing contracts are out of scope.

## Baseline

- `CURRENT_HEAD`: `5a9fa17e2d63a5f7608b2bdeb06763432d945f05`
- `CURRENT_DESIGN_SYSTEM`: existing `Themes/Colors.xaml`, `Typography.xaml`, `Layout.xaml`, `Controls.xaml`; the foundation is reusable but still has mixed semantic and page-specific tokens.
- `CURRENT_NAVIGATION`: `NavigationView` with Home, Recording, Meetings, Series, Transcripts, Speakers, Summaries, Tasks, Search, Analytics, Assistant, Agents, Administration and Settings.
- `CURRENT_PAGE_STRUCTURE`: shared shell plus page-local scroll viewers; Home and Recording use two-column card layouts.
- `CURRENT_REUSABLE_CONTROLS`: `PageHeader`, `DeviceSelector`, `AudioLevelMeter`, `AudioWaveformMonitor`, `ProcessingStepper`, `EmptyState`, `StatusBadge`.

## Findings

1. **Shell overload** — secondary work such as Series, Search, Analytics and Assistant is mixed into the primary navigation. The user cannot immediately distinguish recording, results and system state.
2. **Status overload** — the title bar combines a generic system status, profile and runtime state. A single status string hides which component is degraded.
3. **Home overload** — six KPI cards, quick actions, agent details, notifications, processing and recent meetings compete with the one decision that matters: can I record now?
4. **Recording overload** — the page exposes microphone, system audio, profile, lifecycle, processing and delivery as equally prominent cards. The primary controls are visually diluted and the right rail becomes tall at 1366×768.
5. **Technical copy leaks into the workspace** — Agent, API, ASR and master-file wording appears in ordinary user-facing cards instead of a diagnostics surface.
6. **Responsive risk** — fixed 320/340px rails plus multiple cards and a permanent footer reduce the vertical space available for Start/Pause/Stop at 1366×768.
7. **Selection risk** — `DeviceSelector` is reusable, but the page refresh path must remain visually and behaviorally distinct from user selection. The selector now gets explicit accessible naming and a compact presentation.
8. **Visual inconsistency** — existing styles are mostly coherent, but radius, card density and semantic colors are not expressed through a complete token vocabulary.

## Phase 1 decisions

- Keep the current WinUI 3 resource dictionaries and extend them with semantic aliases; do not add a parallel styling layer.
- Keep the current binding names and click handlers while changing layout hierarchy.
- Primary navigation becomes Main (`Home`, `Recording`, `Meetings`), Results (`Transcripts`, `Summaries`, `Tasks`, `Speakers`) and System (`System status`, `Settings`). Optional routes remain available but are hidden from the daily navigation.
- Home prioritizes readiness, microphone and recent meetings.
- Recording prioritizes the selected microphone, signal, waveform and Start/Pause/Stop. When the `ONLINE` profile is selected, system/render audio is shown as a separate secondary track and is never mixed in the realtime capture path.
- The persistent footer is removed from the main workspace.

## Visual QA limitation

The installed Desktop process was present but did not expose a target window to the Windows capture helper during this audit. The source-level audit and XAML build remain valid; rendered screenshots must be captured after the refreshed Desktop payload is launched successfully.
