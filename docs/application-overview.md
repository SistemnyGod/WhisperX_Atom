# Обзор приложения

## Назначение

WhisperX Atom превращает аудио совещания в проверяемую стенограмму с временными сегментами, спикерами и качественными метаданными. После готовой стенограммы доступны саммари, решения, задачи и локальный ИИ-помощник. Основной принцип — сначала надёжно сохранить и получить текст, затем запускать необязательные аналитические стадии.

## Поддерживаемые рабочие сценарии

### Файл → стенограмма

Пользователь загружает аудио или видео. Файл проходит resumable TUS-загрузку, media processing, ASR WhisperX, alignment и, если доступно, diarization. Результат сохраняется как `READY` или осмысленный `PARTIAL_READY`.

### Кнопка записи → стенограмма

Desktop отправляет Recorder Agent команду preflight и запускает локальную запись. Agent сохраняет микрофон и системный звук отдельными дорожками, режет их на FLAC-чанки и помещает их в SQLite spool. Доставка может продолжаться после временного отключения API. После finalize сервер запускает обычный media/WhisperX путь.

### Голосовая команда → запись

Voice Host распознаёт ограниченный набор команд с wake phrase «Атом» и передаёт их Recorder Service через защищённый Named Pipe. Voice Host не владеет аудиоархивом, spool или серверной обработкой и остаётся экспериментальным слоем управления.

### ИИ-помощник

Assistant работает поверх существующей локальной Qwen и evidence-механизма. Контекст чата фиксируется при создании: одна встреча либо глобальная история для разрешённых ролей. Ответы должны ссылаться на сегменты стенограммы; ошибки Qwen не удаляют уже сохранённую историю.

## Рабочие разделы Desktop

- **Главная** — состояние системы, текущая запись, очередь, последние совещания и быстрые действия.
- **Запись** — preflight, выбор микрофона и системного звука, старт/пауза/продолжение/завершение, локальный архив и доставка.
- **Совещания** — реестр, обработка, transcript workspace, speakers, summary, decisions, tasks и media preview.
- **Стенограммы** — поиск и просмотр доступных transcript-версий.
- **Спикеры** — meeting-local labels, назначение имени и объединение профилей.
- **Саммари** — versioned Summary v2 и evidence-backed результаты.
- **Задачи** — поручения из доступных совещаний.
- **ИИ-помощник** — постоянные разговоры, follow-up вопросы и evidence.
- **Агенты** — локальный Recorder Agent и серверный реестр подключений.
- **Настройки** — API-сессия, регистрация Agent, архив и параметры локального подключения.

Разделы Series, Search, Analytics и Administration присутствуют как части навигационного каркаса, но не являются приоритетом текущего Transcript MVP.

## Состояния результата

| Статус | Значение |
| --- | --- |
| `QUEUED` / `RUNNING` | Задание ожидает worker или выполняется |
| `READY` | Transcript прошёл обязательные проверки |
| `PARTIAL_READY` | Текст сохранён, но alignment, diarization или quality имеют предупреждения |
| `FAILED` | Пригодный текст получить не удалось |
| `CANCELLED` | Обработка отменена пользователем |

Пустая стенограмма не считается готовой. Доступность API и готовность локальной записи — разные состояния: при недоступном сервере Agent продолжает сохранять запись локально.
